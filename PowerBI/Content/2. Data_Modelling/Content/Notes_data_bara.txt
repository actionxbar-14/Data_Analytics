:: [ What is Data Modelling ]




## Data Model : 
- It Describes the business data and how the pieces related to each other. 



- Three Main Component : 



1. Tables :

- Inspect Data ( Raw Data ). 
- Clear Business Structure ( Specific to the domains ).



2.  Relationships : 

- Connect those tables into Each other.
- Design for Consumption.



3. Calculations and Aggregations

- In order to answer business Query.

:: PowerBI Dimensional Modelling :

-> Table : [ Fact Table , Dimension Table ]




1. Fact Table :  [ What happened ]
- It stores business events , transactions or activity that we can use in order to calculate something.
- Every row is showing an event.
- [ Id/keys , Dates and time , Numbers]. 





2. Dimension Table : [ Description 'context' ]
- It describes the context around the facts.
- Every row is describing something about context
- [ category , color  , status].






#### How to Connect Those two tables :  




1. ## STAR SCHEMA : 
- [ It gives PowerBI a clean way to filter the data ].
- [ It helps to apply Easy DAX ]. 
- [ It helps to make Easy Visuls ].




2. ## SnowFlake Schema :
- [ Used for Big Dimension ].
- [ Complex ].
- [ Slower ( too many joins ) ].
- [ Smaller Size ].




3. ## Galaxy Schema :
- [ Used for multiple Facts ].
- [ Never Connect Fact table directly but through an dimension].

i.) Keys. :
- Both table should have one common key.

ii.) Relationship : 
- It is a contract between two tables that defines the rules, helping PowerBI combine data from both in the Visual layer.


iii.) Filter direction :
- left table to right table.
- right table to left table.
- both left to right and right to left.

:: Junk / Flag Dimensions :

- [ So all those junk or garbage , let's say columns that are actually not related to each other and take space inside the facts , we're going to go and bundle them into a junk table , a junk dimension. :: Master Facts [ The Grain ] :

## Grain : 
- The level of details that one row in a fact table represents.
- If two Fact have same grain then we have two options :

1.) Append : [ Append only if they are exactly identical and shape are same ].
2.) Merge  : [ Merge only if they are not in identical shape but have follow one-to-one relationship ].


--> NOTE  : 
- [ If the two fact does not have same grain , does not have same shape , then never ever merge or append or make direct relationship between them]
- [ Such two fact can be combined with related 'Shared Dimensions' that both fact can understand it. ]


--> Shared ( Conformed ) Dimension :
- One Complete dimension that both facts connect to , so you can safely compare their measure.
